# rhwp 고침 (hwp2pdf-rhwp.patch)

바탕: [edwardkim/rhwp](https://github.com/edwardkim/rhwp) `devel` 커밋 `21ed640` (2026-10-09, 판 표기 0.8.7).
`engine\build_rhwp.py` 가 이 커밋을 받아 아래 고침을 넣고 빌드해 `engine\rhwp\` 에 설치한다
(출처는 `engine\rhwp\BUILD.json`). rhwp 와 같은 MIT 라이선스다.

## 어떻게 찾았나

한컴오피스는 문서를 저장할 때 1쪽 그림(미리보기)을 문서 안에 넣는다. 우리 PDF 1쪽을 같은 크기로
그려 **실루엣 일치율**(rhwp 개발진의 Visual Sweep 과 같은 식 — 2px 관용, `engine\fidelity.py`)로
맞대고, 어긋난 띠마다 원인을 rhwp 소스에서 찾아 고쳤다. 한컴 미리보기는 가로세로 0.58% 작게
그려져 있어 같은 비율로 줄여 비교한다.

| 문서 (사용자 시험지 4개, 1쪽) | 0.8.7 릴리스 | 고친 판 |
|---|---:|---:|
| 2단 시험지 (.hwp) | 72.7 | **98.0** |
| 2단 기출문제지 1 (.hwpx) | 82.6 | **99.0** |
| 2단 기출문제지 2 (.hwpx) | 99.7 | 99.7 |
| 2단 시험지 (.hwpx, B4) | 64.7 | **97.8** |
| 평균 | 79.9 | **98.6** |

남은 1~2% 는 거의 글꼴이다 — 한컴 글꼴(함초롬·HY동녘 등)이 없어 대체 글꼴의 글자 모양이 다르다.

회귀 확인 (모두 고친 판 기준):
- rhwp 저장소에 있는 한컴(Hwp 2018~2024)이 직접 만든 PDF 34종 615쪽을 쪽마다 96dpi 로 맞대면
  고치기 전과 쪽 단위로 같다(평균 88.1, 중앙 98.4, 90% 이상 75.6% — 차이 0.05 넘는 쪽 없음).
- rhwp 라이브러리 단위 시험 3,870개 + 크레이트 시험 182개 통과.
- rhwp 통합 시험 6,251개: 고치기 전과 실패 목록이 같다(의도한 골든 1건은 갱신 — 아래 「영향」).
- 영향 범위: rhwp 시험 문서 1,223개 전부를 고치기 전·후 판으로 렌더 트리까지 떠서 비교했다(아래 「영향」).

## 고침

1. **다단 구역 시작 위치** (`layout.rs`, `typeset/section/columns.rs`) — 시험지 서식(1단 안내 →
   2단 본문)에서 2단 본문 전체가 5~10px 아래로 밀렸다.
   - 1단 구역의 마지막 문단에 2단 구분선이 앵커돼 있으면 구역 끝의 '마지막 문단'을 못 찾아 뒤
     줄간격을 빼지 않았다 → 그 앞의 마지막 문단·표를 쓴다.
   - 다단 구역에 글자처럼 취급한 표 한 줄(시험지 머리 표)만 있으면 구역 끝은 그 줄의 저장 아래 끝이다.
   - 쪽 나눔 계산의 흐름 누적값에도 같은 원칙(뒤 줄간격 제외)을 적용.
   - 다단 구역의 머리 표를 1단 '헤더 띠'로 오인해 높이를 한 번 더 더하던 것(+148px)을 1단 구역으로 한정.
2. **정의 없는 글머리표** (`paragraph_layout.rs`) — 문단 머리가 글머리표인데 정의가 비어 있으면(ID 0)
   한/글은 기본 ● 를 그린다. rhwp 는 아무것도 그리지 않았다.
3. **대문자 그리스 문자 수식 명령** (`equation/symbols.rs`) — `DELTA T` 가 ΔT 가 아니라 글자 "DELTA" 로
   찍혔다. 모두 대문자인 이름은 `Delta` 와 같은 기호로 찾는다.
4. **표 칸 안 그림 + 캡션 정렬** (`table_layout.rs`) — 가운데 정렬 칸에 그림과 캡션(「Figure 1」)이
   있으면 한/글은 묶음 전체를 가운데에 둔다. rhwp 는 그림만 가운데에 둬 16px 아래였다.
5. **인라인 1행 표의 행 높이** (`height_measurer.rs`, `typeset/table.rs`, `table_layout.rs`) — 셀 줄은
   저장 위치(vpos)에 그리면서 행 높이는 줄높이+줄간격 합으로 쟀다. 한/글이 어떤 줄을 앞당겨 저장한
   셀(수식 줄 다음 vpos 가 합보다 200HU 앞)에서 행이 2.6px 부풀고 표 아래 전체가 밀렸다. 저장 줄
   사슬 끝 + 안 여백이 **표 개체 높이와 정확히 같고**, 줄이는 양이 가장 작은 저장 줄높이의 절반보다
   작을 때만 그 높이를 쓴다. 앞 조건은 합이 맞는 KTX 목차 같은 반례(rhwp 기록) 때문이고, 뒤 조건은
   대체 글꼴로 글이 한 줄 더 넘친 칸(rhwp 시험 문서 opengov 36382399 머리 표)에 저장 높이를 강제해
   넘친 줄이 칸 밖으로 나가지 않게 하려는 것이다(영향 분석에서 찾음). 한컴 미리보기의 아래 테두리와
   1px 안으로 맞았다.
6. **수식만 있는 줄의 들여쓰기** (`paragraph_layout.rs`) — 본문 흐름에서 첫 줄 들여쓰기가 두 번
   들어가 수식이 줄 시작보다 오른쪽(+12.6px, +32.6px)에 놓였다. 배율 2.0 은 HWP3 변환본·미주용 옛
   보정이다(rhwp 자체 주석 #1472 의 '현재: IR(full)×1.0' 과 같은 값으로 맞춤).
7. **어울림 그림 옆 줄의 내어쓰기** (`paragraph_layout.rs`) — 저장 cs 가 '문단 자신의 여백' 이면
   여백을 지우는 판정(#6706)이 cs=0·여백 0 에서도 참이 되어 내어쓰기까지 지웠다(19.9px). cs > 0 일
   때만 그 판정을 쓴다.
8. **가운데 정렬 문단의 수식 줄** (`paragraph_layout.rs`) — [수식][공백] 줄의 정렬을 늘 끄던 것(#1308)을
   저장 줄이 시작 위치를 담을 때(cs > 0)로 한정했다 — 빈 줄 경로(#5583)와 같은 계약. 한컴은 이 줄을
   가운데에 그렸고 rhwp 는 단 왼끝에 붙였다(40px).

## 고치지 않은 것 (근거가 모자람)

- 수식 안 한글(`~~~그리고~~~`)이 든 수식의 폭: 한컴 미리보기는 저장 폭을 따랐지만, rhwp 는 한컴2024
  대조군(PR #7382)에 근거해 이런 수식만 자체 폭을 쓴다. 문서 하나로 뒤집지 않았다.
- 공백 19칸 뒤 그림의 가로 위치(6px): 공백에 자간을 적용하는 rhwp 규칙(#2279 실측)과 어긋나는 사례
  하나뿐이다.
- 긴 표가 여러 쪽에 걸쳐 나뉠 때의 쪽 나눔(rhwp 시험 문서 86쪽짜리 1종이 남은 손실의 절반) — rhwp 가
  진행 중인 #1891 영역이다.
- 한컴 글꼴(함초롬 등)이 없어 바탕·굴림으로 대체 — 함초롬 글꼴은 사용 허락 범위가 분명하지 않아 이
  도구가 받거나 포함하지 않는다.

## 영향

rhwp 저장소의 시험 문서 1,223개 전부를 고치기 전(devel 21ed640)·후 판으로 렌더 트리(모든 쪽, 노드 좌표
0.1px)까지 떠서 비교했다. 달라진 문서는 **10개**, 쪽 수가 바뀐 문서는 없다(암호 문서 3개는 두 판 모두 열지 못함).

| 달라진 문서 | 무엇 | 한컴 PDF 대조 (rhwp 저장소 `pdf/`) |
|---|---|---|
| issue2217 `20200830` (+ 같은 문서 `basic/issue1994_…`) | 칸 안 그림 6.4px 위로 (고침 4) | 89.32 → **90.58** |
| issue6284 `child_policy_top_caption_charts` 6쪽 | 칸 안 그림 위치 (고침 4) | 95.47 → **98.32** |
| issue7182 `rowbreak_cell_picture_only_paragraph` 2쪽 | 칸 안 그림 위치 (고침 4) | 37.80 → 37.87 |
| task1725 `text_footnote_tail_overpagination` (hwp·hwpx) 122·217쪽 | 칸 안 그림 위치 (고침 4) | 98.51 → 98.52, 99.48 → 99.61 |
| task2070 시장구조조사 30쪽 | 칸 안 그림 위치 (고침 4) | 98.99 → 99.04 |
| issue6179 `right_tab_footer_logo` | 칸 안 그림 0.7px 위로 (고침 4) | rhwp 가 이 문서의 PDF 를 만들지 못함(두 판 모두) |
| issue6194 `156494392_agri_press_release` | 칸 안 그림 6.6px 위로 (고침 4) | 기준 PDF 없음 |
| task1706 `empty_para_before_pagebreak` 3쪽 | 정의 없는 글머리표 ● (고침 2) | 기준 PDF 없음 — 한컴 저장본, 사용자 시험지와 같은 형상(글머리표 정의 0개 + 문단 머리 BULLET id 0) |

기준이 있는 쪽은 모두 같거나 나아졌다. 영향 분석으로 고침 5 의 반례(opengov 머리 표)를 찾아 위 가드를 더했다.

rhwp 통합 시험: 시험 원본 1,477개 중 별도 대상(예외 14개)과 이 빌드에 없는 기능·자료가 필요한 8개를 뺀
1,455개를 한 묶음으로 고치기 전·후 두 번 돌렸다. 6,251개 중 실패 목록은 두 판이 같고(308개 — 이 작업용
부분 체크아웃에 없는 `pdf/`·`bindings/`·스킬 문서 등을 읽는 시험), **고친 판에서만 실패한 것은 하나**였다:
`equation_command_goldens` 의 `over_greek` — `ALPHA OVER BETA` 의 현행 엔진 잠금 골든이 글자 "ALPHA"
대신 Α 가 나와 달라졌다. 의도한 변경(고침 3)이므로 시험이 안내하는 대로 골든을 갱신해 패치에 넣었다
(`src/renderer/equation/fixtures/m09_expand/over_greek.golden`).
